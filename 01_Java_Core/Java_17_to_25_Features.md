# 🚀 Эволюция Java: Ключевой бэкенд-арсенал от JDK 17 до JDK 25 (LTS)

### 🎯 Главный инсайт (TL;DR)
> Современная Java совершила тектонический сдвиг в сторону лаконичности (Data-Oriented Programming) и облачной производительности. Главный фокус версий 17–25 — это избавление от boilerplate-кода, безопасная работа со структурами данных через Pattern Matching и тотальная оптимизация JVM по памяти.

### ⚙️ Архитектурные особенности (Under the Hood)

#### 1. Революция синтаксиса и данных (JDK 17 – 21)
*   **Records (Записи):** Неизменяемые (immutable) классы-носители данных. Автоматически генерируют конструктор, `equals()`, `hashCode()`, `toString()` и геттеры без boilerplate-кода.
*   **Sealed Classes (Запечатанные классы):** Позволяют жестко ограничить круг наследников интерфейса или класса с помощью ключевого слова `permits`. Заставляют компилятор проверять полноту иерархии.
*   **Pattern Matching для switch:** Возможность проверять тип объекта прямо в блоке `switch` и автоматически приводить к нему переменную, избавляя от ручного `instanceof` и кастинга:
    ```java
    return switch (obj) {
        case Integer i -> "Число: " + i;
        case String s  -> "Строка длиной: " + s.length();
        case null      -> "Объект null";
        default        -> "Неизвестный тип";
    };
    ```
*   **Record Patterns:** Позволяют распаковывать (деструктурировать) `Record` прямо на лету внутри `instanceof` или `switch`: `case Order(String id, int price) -> ...`
*   **Sequenced Collections:** Введение единых интерфейсов (`SequencedCollection`, `SequencedSet`, `SequencedMap`) для коллекций, имеющих четкий порядок элементов. Добавились методы `getFirst()`, `getLast()`, `addFirst()`, `reversed()`.

#### 2. Прорывные фичи современной Java (JDK 22 – 25 LTS)
*   **Unnamed Variables & Patterns (Java 22):** Возможность использовать символ подчеркивания `_` для неиспользуемых переменных (например, в catch-блоках исключений или лямбдах): `catch (NumberFormatException _)`.
*   **Flexible Constructor Bodies (Java 22–25):** Снято историческое ограничение, требовавшее вызова `super()` строго первой строчкой конструктора. Теперь до вызова конструктора родителя можно выполнять логику валидации аргументов или предварительных расчетов.
*   **Stream Gatherers (Java 22–24):** Точка расширения для Stream API. Позволяет писать кастомные промежуточные операторы для стримов (например, скользящее окно, разбиение на батчи), чего не позволял базовый метод `map`/`filter`.
*   **Compact Object Headers (Java 24–25):** Низкоуровневая оптимизация в JVM (JEP 519). Заголовок любого Java-объекта на 64-битных системах сокращен с 96–128 бит до ровно 64 бит (8 байт). Это автоматически снижает потребление оперативной памяти (Heap) приложением на 10–20% вообще без изменения кода!

### 💣 Ловушки на собеседованиях (Interview Traps)

*   ❌ **Вопрос:** «Является ли класс-Record полностью глубоко неизменяемым (Deeply Immutable)?»
*   ✅ **Ответ:** **Нет, не является.** Поля самого Record неявно помечены как `final`, их ссылки изменить нельзя. Но если одним из полей является мутабельный объект (например, обычный `java.util.ArrayList`), то вы всё еще можете добавлять или удалять элементы из этого списка. 
*   💡 **Как лечить:** Для обеспечения полной неизменяемости нужно в кастомном конструкторе Record оборачивать коллекции в `List.copyOf()`.

*   ❌ **Вопрос:** «Зачем нужны Sealed-классы бэкенд-разработчику, если есть обычные модификаторы доступа?»
*   ✅ **Ответ:** Главный плюс — **проверка компилятором на полноту (Exhaustiveness)** при использовании `switch`. Если вы делаете `switch` по sealed-интерфейсу, у которого разрешено всего 3 реализации, компилятор Java точно знает все возможные исходы. Вам больше **не нужно писать ветку `default`**. Если завтра другой разработчик добавит 4-го наследника в `permits`, проект просто не скомпилируется, пока во всех `switch` кодовой базы не появится обработка нового типа. Это полностью исключает логические ошибки при расширении системы.
