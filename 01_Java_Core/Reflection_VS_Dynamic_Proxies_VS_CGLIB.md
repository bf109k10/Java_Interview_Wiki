# 🚀 Сравнение Reflection, JDK Dynamic Proxies и CGLIB

Все три инструмента используются для анализа и модификации поведения классов во время выполнения (динамически), но решают разные задачи. Reflection позволяет исследовать и вызывать код напрямую, в то время как JDK Dynamic Proxies и CGLIB создают «обертки» (прокси) для перехвата вызовов методов.
#aop

### 🎯 Главный инсайт (TL;DR)
> *   Используйте **Reflection**, когда вам нужно программно проанализировать класс (получить список методов, аннотаций) или получить доступ к приватным полям. Для вызова методов в обычной логике применять его не рекомендуется из-за низкой производительности.
*   Выбирайте **JDK Dynamic Proxies**, если разрабатываете архитектуру на основе интерфейсов и хотите добавить логику перехвата (например, логирование, транзакции в Spring), при этом не создавая тяжеловесных сборок байт-кода.
*   Применяйте **CGLIB**, если проксируемый класс не реализует интерфейсы или требуется перехват вызовов между методами внутри самого объекта. Учитывайте, что создание CGLIB-прокси занимает больше времени памяти из-за манипуляций с байт-кодом.


### Сравнение механизмов

| Характеристика | Reflection | JDK Dynamic Proxies | CGLIB |
| :--- | :--- | :--- | :--- |
| **Основная суть** | Анализ структуры (классы, методы) и вызов логики через метаданные. | Реализация **интерфейсов** для создания прокси. | Создание **наследников** (subclassing) целевого класса. |
| **Ограничения** | Ограничений по типам нет (работает с чем угодно, включая приватные поля/методы). | Требует обязательного наличия интерфейсов у целевого класса. | Не работает с классами `final` и методами `final` (нельзя создать подкласс). |
| **Принцип работы** | Использование пакета `java.lang.reflect`. | Имплементация интерфейса `InvocationHandler`. | Генерация байт-кода нового класса на лету через библиотеку ASM. |
| **Производительность** | Медленнее прямого вызова (требует поиска в метаданных). | Медленнее прямого вызова, но быстрее CGLIB при создании, медленнее при вызовах. | Высокая скорость выполнения (прямой вызов метода предка), но затратный процесс создания класса. |
| **Где используется** | Десериализация, фреймворки тестирования (JUnit), аннотации. | Spring AOP (по умолчанию при наличии интерфейсов), удаленные вызовы (RMI). | Spring AOP (когда класс не реализует интерфейсы), Hibernate (lazy-loading). |
