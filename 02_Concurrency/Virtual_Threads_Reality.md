# 🧵 Виртуальные потоки в Java 21+ (Project Loom)

### 📌 Суть технологии
Запуск миллионов «дешевых» потоков в памяти поверх физических потоков ОС (Carrier Threads). Идеально для **I/O-bound** задач (ожидание БД/сети).

### ❌ Почему «не взлетели» на старте (Критические проблемы Java 21-23)
1. **Thread Pinning (Закалывание):** Если внутри виртуального потока вызывается блок `synchronized`, он намертво блокирует поток ОС. Древние JDBC-драйверы рушили всю производительность.
2. **Вынос пулов БД:** Миллион потоков мгновенно забивали стандартный пул соединений (HikariCP из 30 коннектов) и падали по таймауту.
3. **ThreadLocal OOM:** Фреймворки (Spring) хранили тяжелые контексты безопасности в `ThreadLocal`. При 100k+ потоках память мгновенно заканчивалась.

### ✅ Как дела обстоят сейчас (Java 24+)
* **JEP 491 (Java 24):** Полностью переписана JVM. Блоки `synchronized` больше НЕ привязывают виртуальный поток к ОС.
* **Стандарт индустрии:** В Spring Boot 3.2+ включается одной строчкой: `spring.threads.virtual.enabled=true`. Применяется подход *Pragmatism over Purism* — 95% производительности реактивщины без изменения кода.

### ❓ Вопросы на собеседовании:
* *В чем разница между виртуальным и платформенным потоком?*
* *Что такое Thread Pinning и как его лечить?* (Ответ: Переход на Java 24+ или замена `synchronized` на `ReentrantLock`).
