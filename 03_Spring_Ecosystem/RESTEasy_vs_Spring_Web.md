# ⚡ HTTP-стеки: RESTEasy (Classic/Reactive) vs Spring MVC
#spring #quarkus #resteasy #reactive #high-load 

### 🎯 Главный инсайт (TL;DR)
> Выбор между Spring MVC и RESTEasy Reactive — это выбор между традиционной потоковой моделью (один поток ОС на запрос) и современной гибридной Event Loop архитектурой. RESTEasy Reactive (эксклюзив Quarkus) позволяет писать простой императивный код, но выполнять его с реактивной производительностью без использования сложного синтаксиса `Mono`/`Flux`.

### ⚙️ Архитектурные особенности (Under the Hood)

#### 1. RESTEasy Classic vs RESTEasy Reactive
*   **RESTEasy Classic:** Традиционная реализация стандарта Jakarta RESTful Web Services (JAX-RS). Работает по классической блокирующей модели: один запрос пользователя полностью захватывает один физический поток сервера приложений (Tomcat/WildFly). Если поток ждет ответа от базы данных, он простаивает, неэффективно расходуя память.
*   **RESTEasy Reactive:** Глубокая эволюция движка, созданная специально под Quarkus на базе сетевого ядра **Vert.x**. Вместо тысяч потоков он использует фиксированное количество потоков ввода-вывода (**Event Loop**). 
    *   Если ваш метод не делает блокирующих операций, он выполняется прямо на Event Loop со скоростью света.
    *   Если Quarkus видит, что метод возвращает блокирующий тип данных (или над ним стоит аннотация `@Blocking`), он автоматически и прозрачно перенаправляет его в фоновый рабочий пул (Worker Thread Pool), не замораживая Event Loop.

#### 2. RESTEasy Reactive vs Spring WebFlux
В отличие от Spring WebFlux, который заставляет разработчика переписывать весь код под функциональный реактивный стиль (Project Reactor) и оборачивать все данные в типы `Mono` и `Flux`, RESTEasy Reactive дает **реактивность под капотом при сохранении императивного стиля кода**. Код выглядит как обычная Java, но держит колоссальные параллельные нагрузки.

### 💣 Ловушки на собеседованиях (Interview Traps)

*   ❌ **Вопрос:** «Можно ли подключить и использовать RESTEasy Reactive в проекте на Spring Boot, чтобы ускорить обработку HTTP-запросов?»
*   ✅ **Ответ:** **Нет, нельзя.** RESTEasy Reactive — это эксклюзивная часть экосистемы Quarkus. Его высокая скорость и логика переключения потоков завязаны на внутренние механизмы оптимизации Quarkus в момент сборки проекта (Build-Time). В мире Spring Boot для схожих задач высокой параллельности используются **Spring WebFlux** (реактивный подход на Netty) либо **Spring MVC + Virtual Threads** (начиная с Java 21+).

*   ❌ **Вопрос:** «Что произойдет в RESTEasy Reactive, если я случайно вызову тяжелый блокирующий метод (например, `Thread.sleep()` или старый JDBC-запрос) внутри метода, который Quarkus посчитал реактивным?»
*   ✅ **Ответ:** Это приведет к **блокировке потока Event Loop (Blocker Error)**. Так как потоков Event Loop очень мало (обычно по числу ядер CPU), блокировка хотя бы одного из них мгновенно снизит пропускную способность сервера. Если заблокировать их все, сервер полностью перестанет принимать новые HTTP-запросы, а в логах Quarkus появится грозное предупреждение: `Thread Thread[...] has been blocked for ... ms`.
*   💡 **Как лечить:** Явно помечать такие методы аннотацией `@Blocking`.
