# 🏛️ Модули Веб-стека Spring: spring-web против spring-webmvc
#spring #mvc #webflux #architecture #mid-senior

### 🎯 Главный инсайт (TL;DR)
> `spring-web` и `spring-webmvc` — это не конкурирующие модули, а уровни одной архитектуры. `spring-web` является общим низкоуровневым инфраструктурным фундаментом для всех веб-приложений экосистемы, в то время как `spring-webmvc` (Spring MVC) — это конкретная реализация синхронного блокирующего фреймворка над ним.

### ⚙️ Архитектурные особенности (Under the Hood)

#### 1. Модуль `spring-web` (Базовый фундамент)
Этот модуль содержит общие классы, интерфейсы и утилиты, необходимые **для любого веб-взаимодействия**, независимо от того, синхронное оно или реактивное. Сам по себе он не умеет маршрутизировать запросы к контроллерам.
*   **Что внутри:** Интеграция с веб-контейнерами (Tomcat, Jetty), HTTP-клиенты (`RestTemplate`, современный `RestClient`), базовые HTTP-утилиты (`HttpHeaders`, `HttpStatus`, `ResponseEntity`) и конвертеры данных (`HttpMessageConverter`), которые с помощью библиотеки Jackson превращают Java-объекты в JSON и обратно.

#### 2. Модуль `spring-webmvc` (Spring MVC)
Это полноценная реализация паттерна Model-View-Controller (MVC) для сервлетных контейнеров, построенная *поверх* модуля `spring-web`. Работает по классической синхронной блокирующей модели (Thread-per-Request).
*   **Что внутри:** Главный распределитель запросов **`DispatcherServlet`** (сердце Spring MVC), поддержка аннотаций `@RestController`, `@GetMapping`, `@PostMapping`, `@ControllerAdvice` (глобальная обработка ошибок) и механизмы рендеринга HTML-страниц (Thymeleaf, JSP).

```text
       ┌────────────────────────────────────────────────────────┐
       │                 spring-web (Фундамент)                 │
       │  (HTTP-статусы, Конвертеры JSON, RestTemplate/Client)  │
       └───────────────────────────┬────────────────────────────┘
                                   │ (используется как база для...)
            ┌──────────────────────┴──────────────────────┐
            ▼                                             ▼
┌───────────────────────────────┐             ┌───────────────────────────────┐
│     spring-webmvc (MVC)       │             │     spring-webflux (Flux)     │
│ (DispatcherServlet, Tomcat)   │             │   (Event Loop Netty, Reactive)│
└───────────────────────────────┘             └───────────────────────────────┘
```

#### 3. Почему важно это разделение?
Разделение позволило Spring изолировать базовую работу с HTTP-протоколом от конкретного движка выполнения. Когда появился реактивный стек **Spring WebFlux**, разработчики Spring просто создали модуль `spring-webflux` *вместо* `spring-webmvc`, но сохранили в его основе тот же самый базовый `spring-web`.

### 💣 Ловушки на собеседованиях (Interview Traps)

*   ❌ **Вопрос:** «Если я подключаю в Maven/Gradle зависимость `spring-boot-starter-web`, какой веб-стек я получу под капотом и какие модули туда прилетят?»
*   ✅ **Ответ:** Вы получите классический синхронный блокирующий стек **Spring MVC**. Стартер `spring-boot-starter-web` автоматически скачает по цепочке:
    1. Модуль `spring-webmvc` (для работы контроллеров и DispatcherServlet).
    2. Модуль `spring-web` (как базу для работы с HTTP и JSON).
    3. Встроенный веб-сервер **Tomcat** (работающий по умолчанию на порту 8080).
    4. Библиотеку **Jackson** (для автоматической сериализации объектов в JSON).

*   ❌ **Вопрос:** «Какова роль `DispatcherServlet` в Spring MVC? Опишите верхнеуровневый путь HTTP-запроса».
*   ✅ **Ответ:** `DispatcherServlet` реализует паттерн Front Controller — он является единой точкой входа для всех запросов приложения. 
    1. Запрос приходит от Tomcat в `DispatcherServlet`.
    2. Он обращается к `HandlerMapping`, чтобы узнать, какой именно `@RestController` и метод отвечают за этот URL.
    3. Вызывается `HandlerAdapter`, который берет на себя физический запуск метода твоего контроллера (и внедрение аргументов).
    4. Метод контроллера возвращает данные (например, Java-объект).
    5. `DispatcherServlet` пропускает объект через `HttpMessageConverter` (Jackson) из модуля `spring-web`, превращая его в JSON-строку, и отправляет клиенту.
