# Как устроен Spring Boot под капотом: Автоконфигурация

Вопрос "Расскажи, как работает `@SpringBootApplication`" задают на 90% собеседований. На него нельзя отвечать "Оно просто само все настраивает".

### 1. Анатомия `@SpringBootApplication`
Эта аннотация — просто ярлык (shortcut) для трех других важнейших аннотаций:

1. `@SpringBootConfiguration`: Тот же `@Configuration`, помечает класс как источник бинов.
2. `@ComponentScan`: Указывает Spring, в каких пакетах искать ваши `@Component`, `@Service`, `@Repository`. По умолчанию ищет в текущем пакете и всех вложенных.
3. `@EnableAutoConfiguration`: **Самый главный движок.** Именно он включает магию автоматической настройки.

---

### 2. Как работает `@EnableAutoConfiguration`?
1. Внутри этой аннотации скрыт импорт специального класса, который сканирует файлы метаданных внутри всех подключенных jar-библиотек (стартеров).
2. В старых версиях Spring Boot это был файл `META-INF/spring.factories`, в современных (Spring Boot 3+) — файл `META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports`.
3. В этих файлах написан огромный список стандартных конфигурационных классов (например, `DataSourceAutoConfiguration`, `RabbitAutoConfiguration`).
4. Spring Boot загружает этот список и пытается применить каждую конфигурацию к вашему проекту.

---

### 3. Условная магия: Семейство `@Conditional`
Spring Boot не включает все конфигурации подряд. Он проверяет условия с помощью аннотаций условной загрузки:

* `@ConditionalOnClass`: Конфигурация сработает только если в classpath проекта есть определенный класс. *(Пример: `DataSourceAutoConfiguration` активируется, только если вы подключили драйвер базы данных вроде H2 или PostgreSQL).*
* `@ConditionalOnMissingBean`: Конфигурация создаст бин по умолчанию, **только если сам разработчик не создал такой бин**. *(Это позволяет вам легко переопределять стандартное поведение Spring).*
* `@ConditionalOnProperty`: Конфигурация включится, только если в файле `application.properties` прописано определенное свойство с нужным значением.

> 💡 **Резюме для интервью**: Spring Boot — это не магия. Это просто огромный набор готовых `@Configuration` классов, которые лежат в стартерах и активируются с помощью аннотаций `@Conditional...` в зависимости от того, какие зависимости вы добавили в `pom.xml` или `build.gradle`.
