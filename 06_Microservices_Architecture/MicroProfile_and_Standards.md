# 🧩 Стандарты MicroProfile в Enterprise Облачной Разработке

### 🎯 Главный инсайт (TL;DR)
> **MicroProfile** — это открытый индустриальный стандарт и набор спецификаций, созданный консорциумом вендоров (Red Hat, IBM, Oracle) как облегченная, Cloud-Native эволюция Java EE. Он предоставляет стандартизированные инструменты для микросервисов, позволяя коду быть независимым от конкретного фреймворка (Quarkus, Helidon, Open Liberty).

### ⚙️ Архитектурные особенности (Under the Hood)

#### 1. Философия: Стандарты против Вендор-лока (Vendor Lock-in)
В мире Spring Boot вы полностью привязаны к проприетарной экосистеме Spring (например, Spring Cloud, Spring Actuator). Если вы захотите уйти со Spring, вам придется переписать 100% кода. 
В мире MicroProfile вы пишете код на базе чистых интерфейсов-спецификаций. **Quarkus** является лишь одной из сред исполнения (runtime). Вы можете взять этот же микросервис и без изменения кода запустить его на сервере *Open Liberty* или *Helidon*, потому что аннотации стандартизированы.

#### 2. Ключевое трио спецификаций в бою
Интервьюеры любят спрашивать, как именно стандарты MicroProfile решают базовые облачные задачи:

*   **MicroProfile Fault Tolerance (Отказоустойчивость):** Декларативная защита межсервисных вызовов с помощью аннотаций:
    *   `@Timeout(value = 2, unit = ChronoUnit.SECONDS)` — жесткое прерывание зависшего запроса.
    *   `@Retry(maxRetries = 3)` — автоматический повтор операции при сбое сети.
    *   `@CircuitBreaker(requestVolumeThreshold = 4, failureRatio = 0.5)` — размыкатель цепи. Если соседний сервис падает, прокси мгновенно перестает слать туда запросы, отдавая дефолтный ответ, спасая кластер от каскадного падения.
    *   `@Fallback(fallbackMethod = "localCacheBackup")` — альтернативный метод, если основной сервис недоступен.
*   **MicroProfile Health (Метрики живучести):** Автоматически генерирует эндпоинты для оркестратора Kubernetes:
    *   `/health/live` (Liveness probe) — отвечает K8s, не завис ли сам контейнер (если упал — K8s его прибьет и перезапустит).
    *   `/health/ready` (Readiness probe) — отвечает, готов ли сервис принимать бизнес-трафик (подключился ли он к БД и брокерам). Если не готов — K8s временно убирает его из балансировщика трафика.
*   **MicroProfile Rest Client:** Позволяет вызывать сторонние API декларативно. Вы пишете простой Java-интерфейс, размечаете его аннотациями JAX-RS и вешаете `@RegisterRestClient`. Среда выполнения сама сгенерирует HTTP-клиент под капотом.

### 💣 Ловушки на собеседованиях (Interview Traps)

*   ❌ **Вопрос:** «Чем концептуально отличается подход к конфигурации приложения в MicroProfile Config от традиционного подхода в Spring Boot (`application.properties`)?»
*   ✅ **Ответ:** MicroProfile Config жестко стандартизирует **приоритетность источников конфигурации (Config Sources)** по умолчанию. Это позволяет гибко управлять конфигурацией в Docker/Kubernetes без пересборки артефакта:
    1. Переменные окружения ОС (Environment Variables) — приоритет 300 (перебивают всё).
    2. Системные свойства Java (`-Dmy.prop=val`) — приоритет 400.
    3. Файл `META-INF/microprofile-config.properties` внутри jar-архива — приоритет 100 (базовые дефолты).
*   В Spring Boot порядок загрузки свойств сложнее и специфичен для фреймворка. В MicroProfile любой разработчик, независимо от рантайма (Quarkus или Helidon), точно знает шкалу приоритетов конфигов на память.
