# Уровни изоляции транзакций (Isolation Level)
#transactional 
> **Источник**: [proselyte.net/transactional-annotation/](https://proselyte.net/transactional-annotation/)  
---

## 📌 Определение

**Уровень изоляции транзакций** — это набор правил, определяющих, как изменения, сделанные одной транзакцией, видны другим параллельным транзакциям. Чем выше уровень изоляции, тем строже правила, но ниже производительность из-за блокировок.

---

## 📊 Уровни изоляции (по стандарту SQL-92)


| Уровень              | Описание                                                                                                                                                  | Проблемы                                                                                                 | Пример использования                                                                        |
| -------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| **READ UNCOMMITTED** | Самый слабый уровень. Транзакция видит **незакоммиченные** изменения других транзакций.                                                                   | Грязное чтение (Dirty Read), Неповторяемое чтение (Non-Repeatable Read), Фантомное чтение (Phantom Read) | Редко используется, только для чтения данных, где не важна точность (например, статистика). |
| **READ COMMITTED**   | Транзакция видит только **закоммиченные** изменения других транзакций.                                                                                    | Неповторяемое чтение, Фантомное чтение                                                                   | Стандартный уровень в PostgreSQL, Oracle, SQL Server. Подходит для большинства приложений.  |
| **REPEATABLE READ**  | Гарантирует, что если транзакция прочитала строку, то повторное чтение той же строки даст тот же результат (даже если другая транзакция изменила данные). | Фантомное чтение                                                                                         | Используется в MySQL (по умолчанию), когда нужно избежать неповторяемого чтения.            |
| **SERIALIZABLE**     | Самый строгий уровень. Гарантирует полную изоляцию: транзакции выполняются так, как будто они идут последовательно одна за другой.                        | Отсутствуют                                                                                              | Критически важные данные, где важна абсолютная целостность (например, финансовые операции). |

## 🔍 Проблемы параллелизма

### 1. **Грязное чтение (Dirty Read)**

- **Описание**: Транзакция читает данные, которые были изменены другой транзакцией, но ещё не закоммичены.
- **Пример**: Транзакция A меняет баланс счета с 100 на 200, но не коммитит. Транзакция B читает баланс как 200. Если A откатывается, B получает неверные данные.
- **Решение**: Уровни изоляции **READ COMMITTED и выше**.

### 2. **Неповторяемое чтение (Non-Repeatable Read)**

- **Описание**: Транзакция читает одну и ту же строку дважды, но между чтениями другая транзакция изменила её и закоммитила.
- **Пример**: Транзакция A читает баланс счета (100). Транзакция B меняет баланс на 200 и коммитит. Транзакция A снова читает баланс и получает 200.
- **Решение**: Уровни изоляции **REPEATABLE READ и выше**.

### 3. **Фантомное чтение (Phantom Read)**

- **Описание**: Транзакция выполняет запрос с условием (например, `WHERE balance > 100`), получает набор строк. Другая транзакция добавляет новую строку, соответствующую условию, и коммитит. При повторном выполнении запроса первая транзакция видит новую строку («фантом»).
- **Пример**: Транзакция A выбирает все счета с балансом > 100 (получает 5 строк). Транзакция B добавляет новый счет с балансом 150 и коммитит. Транзакция A снова выполняет запрос и получает 6 строк.
- **Решение**: Уровень изоляции **SERIALIZABLE**.

## 💡 Как задать уровень изоляции в Spring

В Spring уровень изоляции указывается в аннотации `@Transactional`:

```java
@Transactional(isolation = Isolation.READ_UNCOMMITTED) // Самый слабый
@Transactional(isolation = Isolation.READ_COMMITTED)    // Стандартный
@Transactional(isolation = Isolation.REPEATABLE_READ)   // Избегает неповторяемого чтения
@Transactional(isolation = Isolation.SERIALIZABLE)      // Самый строгий
```

2. **Знайте проблемы** каждого уровня:
  - `READ UNCOMMITTED`: все проблемы (грязное, неповторяемое, фантомное чтение).
  - `READ COMMITTED`: неповторяемое и фантомное чтение.
  - `REPEATABLE READ`: только фантомное чтение.
  - `SERIALIZABLE`: проблем нет.
3. **Примеры использования**:
  - `READ COMMITTED` — стандарт для большинства приложений.
  - `SERIALIZABLE` — только для критических операций (например, банковские переводы).
