## 1. Введение в Propagation

**Ключевой вопрос на интервью:**  
*Что такое `propagation` в `@Transactional` и зачем он нужен?*

**Ответ:**  
`Propagation` определяет, как метод, аннотированный `@Transactional`, должен вести себя при вызове внутри уже существующей транзакции (вложенный вызов).

Spring управляет транзакциями через **AOP-прокси**. Propagation позволяет контролировать:
- Присоединяться ли к текущей транзакции
- Создавать ли новую независимую транзакцию
- Приостанавливать текущую
- Использовать savepoint для частичного отката

**По умолчанию:** `Propagation.REQUIRED`

**Важно:** Настройки propagation работают **только** при вызове через прокси (вызовы между разными бинами/сервисами).

## 2. Все типы Propagation

### REQUIRED (по умолчанию)
- **Поведение**:
  - Есть внешняя транзакция → **присоединяется** к ней.
  - Нет → создаёт новую.
- **Особенности**:
  - Одна физическая транзакция на всю цепочку вызовов.
  - Настройки вложенного метода (`isolation`, `timeout`, `readOnly`) игнорируются.
  - Исключение в любом методе → rollback **всей** транзакции.
- **Use-case**: Основная бизнес-логика.

### REQUIRES_NEW
- **Поведение**:
  - **Всегда** создаёт **новую независимую** транзакцию.
  - Приостанавливает (suspend) текущую транзакцию.
- **Особенности**:
  - Полная изоляция: commit/rollback одной не влияет на другую.
  - Требует дополнительного соединения с БД.
- **Use-case**: Аудит, логирование, уведомления (должны сохраниться даже при откате основной операции).

### NESTED
- **Поведение**:
  - Есть транзакция → создаёт **вложенную** транзакцию с помощью **savepoint**.
  - Нет → работает как `REQUIRED`.
- **Особенности**:
  - Одна физическая транзакция.
  - Ошибка во вложенной → откат **только до savepoint** (частичный rollback).
  - Лучше всего работает с JDBC (`DataSourceTransactionManager`).
- **Use-case**: Пакетная обработка (ошибка в одной записи не отменяет всю пачку).

### SUPPORTS
- Присоединяется, если транзакция есть.
- Иначе выполняется **без** транзакции.

### NOT_SUPPORTED
- Выполняется **вне** транзакции (приостанавливает существующую).

### MANDATORY
- Обязательно требует существующей транзакции, иначе исключение.

### NEVER
- Требует **отсутствия** транзакции, иначе исключение.

## 4. Важные нюансы и подводные камни

1. **Self-invocation** — вызов метода внутри того же класса игнорирует `@Transactional` и propagation.
2. `@Transactional` работает **только на public** методах.
3. `REQUIRES_NEW` увеличивает потребление соединений из пула.
4. `NESTED` не всегда поддерживается в JTA и некоторых JPA-сценариях.
5. При присоединении (`REQUIRED`) атрибуты `isolation`, `timeout`, `readOnly` вложенного метода игнорируются.
6. Пойманное исключение в `REQUIRED` всё равно может пометить всю транзакцию на rollback.
