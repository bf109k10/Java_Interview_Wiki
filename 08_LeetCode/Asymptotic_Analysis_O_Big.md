# ⏱️ Асимптотический анализ и Магия Big O Нотации

### 🎯 Главный инсайт (TL;DR)
> **Big O нотация** описывает не точное время работы алгоритма в миллисекундах, а **скорость роста времени выполнения (или памяти) при увеличении объема входных данных (N) в худшем сценарии**. Главное правило инженера — отбрасывать константы и выделять только доминирующий фактор, определяющий масштабируемость системы.

### ⚙️ Физика процессов (Under the Hood)

#### 1. Шкала измерения Big O (От лучшего к худшему)
1.  **O(1) — Константное время:** Время работы не зависит от N. Выборка элемента из `HashMap` по ключу, чтение элемента из массива по индексу, пуш в стек.
2.  **\(O(\log N)\) — Логарифмическое время:** На каждом шаге объем данных уменьшается вдвое. Бинарный поиск в отсортированном массиве, поиск в B-Tree индексе базы данных.
3.  **O(N) — Линейное время:** Время растет пропорционально N. Один проход циклом по массиву, поиск элемента в связном списке (LinkedList).
4.  **\(O(N \log N)\) — Линейно-логарифмическое время:** Стандарт для эффективных сортировок (`MergeSort`, `QuickSort`, `Arrays.sort()` в Java).
5.  **O(N²) — Квадратичное время:** Вложенный цикл по тем же данным. Брутфорс-решения, сортировка пузырьком. Гроза High-Load систем.
6.  **\(O(2^N)\) или O(N!) — Экспоненциальное / Факториальное время:** Полный перебор всех подмножеств или перестановок (задача коммивояжера). Смерть для production.

```text
Скорость роста времени (Масштабируемость):
▲
│                                     / O(N²) — Квадратичная (Плохо)
│                                    /
│                                   /  / O(N log N) — Сортировки
│                                  /  /
│                                 /  /  / O(N) — Линейная
│                                /  /  /
│                               /  /  /   / O(log N) — Логарифм (Отлично)
│───────────────────────────────┴──┴──┴───┴───────────────────────► Объем данных (N)
```

#### 2. Три золотых правила расчета Big O
*   **Правило 1: Худший сценарий (Worst Case).** Если мы ищем число в массиве циклом, и оно может быть первым ($O(1)$) или последним ($O(N)$) — Big O всегда оценивается по худшему исходу: **$O(N)$**.
*   **Правило 2: Отбрасывание констант.** Если код делает два независимых последовательных прохода по массиву, это $O(2N)$. Константа `2` отбрасывается. Итоговая сложность: **$O(N)$**.
*   **Правило 3: Выделение доминирующего фактора.** Если алгоритм делает $O(N^2 + N)$, то при $N = 1,000,000$ одиночный плюс $N$ не играет никакой роли. Маленькие слагаемые стираются. Итог: **$O(N^2)$**.
