# 💣 Ловушки на собеседованиях: Анализ сложности кода (Big O)

Ниже приведены реальные куски кода, на которых интервьюеры любят ловить кандидатов, проверяя, умеет ли инженер "читать" физику выполнения алгоритма.

---

### 🔥 Ловушка 1: Независимые переменные
*   ❌ **Вопрос:** «Какова сложность данного кода по времени?»
```java
void printPairs(int[] arrayA, int[] arrayB) {
    for (int a : arrayA) {
        for (int b : arrayB) {
            System.out.println(a + "," + b);
        }
    }
}
```
*   ⚠️ **Неправильный ответ из-за зазубривания:** «Здесь вложенный цикл, значит $O(N^2)$!»
*   ✅ **Правильный технический ответ:** **$O(A \cdot B)$**, где $A$ — длина первого массива, а $B$ — длина второго. Мы не имеем права писать $N^2$, так как массивы могут быть абсолютно разного размера (например, в первом 10 элементов, а во втором — миллион).

---

### 🔥 Ловушка 2: Вложенный цикл с уменьшающимся шагом
*   ❌ **Вопрос:** «Какова сложность этого алгоритма?»
```java
void printUnorderedPairs(int[] array) {
    for (int i = 0; i < array.length; i++) {
        for (int j = i + 1; j < array.length; j++) {
            System.out.println(array[i] + "," + array[j]);
        }
    }
}
```
*   ⚠️ **Неправильный ответ:** «Внутренний цикл уменьшается, значит это $O(N \log N)$!»
*   ✅ **Правильный технический ответ:** **$O(N^2)$**. 
*   **Доказательство:** В первый раз внутренний цикл делает $N-1$ итераций, потом $N-2$, потом $N-3$... и так до 1. Общее число итераций — это сумма арифметической прогрессии: $\frac{N \cdot (N - 1)}{2} = \frac{N^2 - N}{2}$. Отбрасываем константы (деление на 2) и недоминирующие факторы (минус $N$). Остается чистое $O(N^2)$.

### 🔥 Ловушка 3: Обманчивый логарифм (Цикл с делением)
*   ❌ **Вопрос:** «Что здесь по сложности времени?»
```java
void bizzareLoop(int n) {
    for (int i = n; i > 0; i /= 2) {
        System.out.println(i);
    }
}
```
*   ⚠️ **Неправильный ответ:** «Обычный цикл от $N$ до 0, значит $O(N)$».
*   ✅ **Правильный технический ответ:** **$O(\log N)$**. Шаг цикла не уменьшается на 1 (`i--`), а **делится на 2** (`i /= 2`). Это классическое определение логарифма по основанию 2. Если $N = 32$, цикл выполнится всего 6 раз ($32 \rightarrow 16 \rightarrow 8 \rightarrow 4 \rightarrow 2 \rightarrow 1$).

### 🔥 Ловушка 4: Скрытая сложность строк в Java (Сложность по памяти)
*   ❌ **Вопрос:** «Какова сложность по времени и памяти у этого метода?»
```java
String stringBuilderTrap(int n) {
    String str = "";
    for (int i = 0; i < n; i++) {
        str += "x"; // Конкатенация строк в цикле
    }
    return str;
}
```
*   ⚠️ **Неправильный ответ:** «Цикл идет до $N$, значит по времени $O(N)$, память $O(1)$».
*   ✅ **Правильный технический ответ:** Время **$O(N^2)$**, Память **$O(N^2)$**.
*   **Низкоуровневое объяснение:** Строки (`String`) в Java неизменяемы (immutable). При каждой конкатенации `str += "x"` Java не просто дописывает букву, а физически создает в куче (Heap) **абсолютно новую строку** и полностью копирует туда все старые символы. 
*   На 1-м шаге копируется 1 символ, на 2-м — 2, на $N$-м — $N$ символов. Суммарно мы делаем $1 + 2 + 3 + ... + N = O(N^2)$ операций копирования и забиваем мусором Heap на $O(N^2)$ байт, заставляя страдать Garbage Collector.
*   💡 **Как лечить:** Использовать `StringBuilder`, который работает на изменяемом массиве внутри и делает добавление за $O(1)$ в среднем (итоговое время упадет до $O(N)$, память до $O(N)$).
